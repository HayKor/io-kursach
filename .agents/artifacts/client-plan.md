# План разработки клиента СУДВ (Android, Web)

Выполняем вместе, в одной сессии: фаза → автотесты → живая проверка → коммит → следующая фаза. Перед началом фазы перечитать её раздел и «Принятые решения».

## 1. Принятые решения

| Вопрос | Решение | Почему |
|---|---|---|
| Платформы | Android и Web с полным набором функций, общий `client-ui` | Один код экранов; платформенный код только там, где без него нельзя (файлы, адрес сервера) |
| Вёрстка | Адаптивная по ширине окна: узкое — нижняя навигация и один экран, широкое — боковая навигация и «список + детали» | Браузер широкий, смартфон узкий; компоненты Decompose общие, различается только раскладка |
| Модели | DTO из `shared:contract`; UI-модели только там, где экрану нужна другая форма, маппер рядом с компонентом в `client-ui` | Так в отчёте (гл. 06); копии DTO ни от чего не защищают |
| Адрес сервера | В точках входа: Android — `android-app/res/values/api.xml`, Web — `<meta name="sudv-api">` в `index.html` (пусто → адрес страницы) | BuildKonfig — Gradle-плагин; плагины Kotlin Toolchain в preview и плохо поддерживают KMP. Ресурсы работают без экспериментов |
| Вложения (загрузка) | Только системный выбор файла (PDF/JPEG) на Android, `<input type=file>` в вебе | Без разрешений, один сценарий на обеих платформах |
| Скачивание | Android: «Сохранить как» (системный диалог) или «Открыть/Поделиться»; Web: обычное скачивание | Без разрешений на любой версии Android |
| minSdk | 26, как в отчёте («Android 8.0 и выше») | Отчёт не правим |
| targetSdk | 36; `ACCESS_LOCAL_NETWORK` из манифеста убрать | При targetSdk < 37 доступ к локальной сети даётся вместе с `INTERNET`. При targetSdk < 37 документация Android просит его не объявлять и не запрашивать. compileSdk остаётся 37 |
| Тема | Своя палитра Material 3 Expressive, светлая и тёмная по системе; тема в `client-ui` | Одинаково на обеих платформах |
| Веб: адреса и «Назад» | Навигация связана с историей браузера (Decompose Web Navigation, `withWebHistory`), у экранов адреса вида `/penalties/42` | Перезагрузка и ссылки ведут на тот же экран |
| Хостинг веба | Сервер Ktor раздаёт собранный `web-app` на `/` с fallback на `index.html`; в эксплуатации один адрес, CORS не нужен | Один контейнер; адрес API = адрес страницы. CORS остаётся для dev-режима (порт 8081) |
| Офлайн | Нет. Данные загружаются при открытии экрана, есть «Обновить»; после изменений список перезагружается | Отчёт не требует; меньше состояний |
| Проверка фазы | Автотесты логики (компоненты на `FakeApiClient`, мапперы, «Клиент API» на `MockEngine`) + живая проверка в браузере **и** на эмуляторе против настоящего сервера, включая неудачные сценарии | Именно так пойманы CORS, `Error` из fetch и сеть Android 17; Compose UI-тестов нет |
| Отчёт | Правится одной финальной фазой | Правка один раз, по итогу |

## 2. Навигация по ролям

Разделы выводятся из матрицы прав сервера (`.agents/artifacts/server-plan.md`, §1). Кнопки, на которые у роли нет прав, не показываются; сервер всё равно проверяет права сам.

| Раздел | ADMIN | HR | MANAGER |
|---|---|---|---|
| Реестр взысканий | — | всё | своё подразделение, только просмотр |
| Сотрудники | просмотр, создание | всё | своё подразделение, только просмотр |
| Отчёты (сводный, архив) | — | всё | — |
| Учётные записи | всё | — | — |

Персональная карточка и её экспорт — из экрана сотрудника (HR, MANAGER). Профиль (ФИО, роль, подразделение) и «Выйти» — в шапке или навигационной панели.

Адреса в вебе: `/penalties`, `/penalties/{id}`, `/penalties/new`, `/employees`, `/employees/{id}`, `/employees/{id}/card`, `/reports`, `/reports/summary`, `/users`, `/login`.

## 4. Устройство `client-ui`

```
client-ui/src/
  RootComponent.kt, RootContent.kt     // Splash / Login / Main — уже есть
  splash/, login/                      // уже есть
  main/                                // оболочка: разделы по роли, адаптивная навигация
  common/                              // загрузка/ошибка/пусто, форматирование дат и ФИО, диалоги
  theme/                               // палитра, SudvTheme
  platform/                            // интерфейсы платформенных сервисов (IFileService)
  employees/, penalties/, attachments/, reports/, users/
```

- Экран — пара `<Экран>Component` (интерфейс + `Default…`, состояние в `Value<State>`) и `<Экран>Content`. Корутины — `coroutineScope()` Essenty.
- Общее состояние загрузки: `Loading` / `Error(message, retry)` / `Content`. Ошибки — один `catch (e: ApiClientException)`.
- Формы проверяют поля правилами `shared:domain` (`Validation`, `AttachmentRules`) до отправки; окончательная проверка остаётся на сервере.
- Разделы — дочерние стеки внутри `Main`; каждый раздел помнит свою историю.
- Платформенные сервисы — интерфейс в `client-ui`, реализации в `client-data` (`src@android`, `src@web`) через Metro.

## 5. Фазы

### Фаза 0. Фундамент

- `android-app`: `minSdk: 26`, `targetSdk: 36`, убрать `ACCESS_LOCAL_NETWORK`. Проверить, что зависимости собираются под API 26.
- Адрес сервера из точек входа. Android: `res/values/api.xml` → `ApiConfig` в фабрику `AndroidAppGraph`. Web: `<meta name="sudv-api">` в `index.html`, пустое значение → `window.location.origin`. Убрать адреса из `client-data` (`AndroidDataBindings`, `WebDataBindings`).
- Тема: палитра светлая/тёмная, `SudvTheme` в `client-ui`; точки входа применяют только её.
- `common/`: состояние загрузки, экран ошибки с «Повторить», форматирование `LocalDate`/`Instant`, ФИО.
- Проверить заранее, иначе фазы ниже придётся переделывать:
  - есть ли Material 3 Adaptive (`NavigationSuiteScaffold`, list-detail) в каталоге `$compose` или его надо подключать отдельно;
  - библиотека для файлов: FileKit (Android + wasmJs) против своих `expect/actual` — пробная сборка в Kotlin Toolchain;
  - Decompose `withWebHistory` (experimental) собирается и работает в `web-app`.
- Тесты: форматирование, чтение адреса из `<meta>` (пусто / задано).
- Живая проверка: вход на эмуляторе без ручной выдачи разрешений; светлая/тёмная тема на обеих платформах.

**Итог фазы 0.** Все риски сняты без запасных вариантов: `material3-adaptive-navigation-suite` (версия Material 3 из `$compose`) и `adaptive-layout` 1.3.0 собираются; FileKit 0.17.0 есть под Android и Wasm и закрывает выбор, «Сохранить как», «Поделиться»/«Открыть» и `FileKit.download` в браузере; `withWebHistory` и `childStackWebNavigation` есть в Wasm-артефакте Decompose 3.5.0 (сборку и работу проверяем в фазе 1). FileKit потребовал Compose 1.12.2 и kotlinx-serialization 1.12.0 — подняты для всего проекта в `common.module-template.yaml`. Найдено при живой проверке: без корневого `Surface` тема не видна (фон и текст берутся у окна).

### Фаза 1. Оболочка и навигация

- `Main`: разделы по роли (§2), адаптивная навигация (нижняя панель / боковая), шапка с пользователем и «Выйти».
- Веб: `withWebHistory`, адреса из §2, открытие по прямой ссылке (deep link) после входа и после восстановления сессии.
- Тесты: набор разделов для каждой роли; навигация между разделами сохраняет их историю; разбор deep link в конфигурацию.
- Живая проверка: три роли (учётные записи HR и MANAGER создать через Swagger), «Назад» браузера и Android, узкое и широкое окно.

**Итог фазы 1.** Сделано по плану. Добавлено из фазы 7: сервер раздаёт собранный `web-app` из `WEB_DIR` с fallback на `index.html` — без этого в dev каждая перезагрузка на адресе раздела давала 404 (у dev-сервера toolchain нет fallback). ### Фаза 2. Справочник сотрудников

- Список: поиск по ФИО/табельному, фильтр подразделения, «Показать архивных». Детали сотрудника.
- Форма создания и редактирования (подразделения из `/departments`), архивирование с подтверждением.
- Права: ADMIN — просмотр и создание; MANAGER — только просмотр (фильтр подразделения скрыт, сервер ограничивает сам).
- Тесты: фильтры уходят в `employees(...)`; ошибки `DUPLICATE_PERSONNEL_NUMBER`, `VALIDATION_FAILED` показываются у формы; после сохранения список обновляется.
- Живая проверка: CRUD под HR; MANAGER видит только своё подразделение; дубликат табельного номера.

**Итог фазы 2.** Сделано по плану. Раздел — `ChildStack` (список → карточка → форма), а не Child Panels: панели заменяют запись в истории браузера, и «Назад» уходил бы со страницы. Двухколоночная раскладка от 840 dp собрана вручную. Заодно веб-клиент добавлен в Docker-образ сервера (из фазы 7). Мелочи из живой проверки исправлены: короткая подпись «Все» в фильтре, поле подразделения во всю ширину, подсветка строки во время правки, «Повторить» не показывается для «нет прав» и «не найдено».

### Фаза 4. Реестр взысканий

- Реестр: фильтры (статус, ФИО, подразделение, период дат приказа), сортировка и направление; список (узкое окно) или таблица (широкое).
- Карточка взыскания: тип, даты, приказ, дата погашения, оставшиеся дни (`PenaltyRules`), статус, реквизиты досрочного снятия, журнал событий.
- Регистрация взыскания: выбор сотрудника, тип, даты, описание, приказ; проверки `Validation.penalty`.
- Досрочное снятие: диалог с реквизитами приказа, только для `ACTIVE`.
- Широкое окно: реестр и карточка рядом (list-detail).
- Тесты: фильтр → параметры `PenaltyFilter`; оставшиеся дни; снятие недоступно для не-`ACTIVE`; `PENALTY_NOT_ACTIVE` от сервера.
- Живая проверка: полный цикл HR; MANAGER — только просмотр своего подразделения, прямая ссылка на чужое взыскание → сообщение о запрете.

### Фаза 5. Вложения и файлы

- Тесты: файл не того типа или больше лимита не отправляется; `FILE_TOO_LARGE`/`UNSUPPORTED_FILE_TYPE` от сервера показываются.

## 6. Риски, которые проверяем в начале

| Риск | Где проверяем | Запасной вариант |
|---|---|---|
| Material 3 Adaptive нет в `$compose` или не собирается в KTC | Фаза 0 | Своя раскладка по `BoxWithConstraints` с теми же порогами ширины |
| FileKit не собирается в KTC или не умеет «Открыть» на Android | Фаза 0 | `expect/actual`: Android — `ActivityResultContracts.OpenDocument`/`CreateDocument` + `FileProvider`; Web — `<input type=file>` и ссылка `blob:` |
| `withWebHistory` (experimental) ломается | Фаза 0–1 | Только «Назад» браузера без адресов |
| Сборка `web-app` в Docker-образ через KTC | Фаза 7 | Собирать `web-app` на хосте и копировать в образ |
| Библиотеки требуют minSdk > 26 | Фаза 0 | Поднять minSdk и поправить отчёт (обсудить) |
| Toolchain не замечает правку манифеста/ресурсов Android | Каждая фаза | Удалить `build/tasks/_android-app_*`, проверить APK через `aapt2` |
